Handling Data Skew in Spark
You are working on a Spark job that aggregates data based on a key, but you notice that the job is suffering from data skew, leading to long processing times and resource inefficiencies. How would you address and mitigate the effects of data skew in this scenario?
Ideal Answer (5 Star)
Data skew in Spark can be mitigated by redistributing the data more evenly across partitions. One approach is to use a salting technique, where additional random values are appended to the keys to distribute skewed data across multiple partitions. For example, if the key is 'customerId', we could create new keys like 'customerId_1', 'customerId_2', etc., and then aggregate the results before removing the salt. Another approach is to increase the parallelism by adjusting the number of partitions using 'repartition' or 'coalesce'. Additionally, using specialized join strategies like 'skewed join' in Spark SQL can also help. Monitoring the Spark UI for skewed stages and using the 'Data Skew' metrics can guide the adjustments needed.

Temporal Data Analysis
Write a query to find the maximum consecutive days a product was sold without interruption in a `sales` table with columns `product_id` and `sale_date`.
Ideal Answer (5 Star)
WITH DateSequence AS ( SELECT product_id, sale_date, ROW_NUMBER() OVER (PARTITION BY product_id ORDER BY sale_date) AS rn FROM sales ), DateGroups AS ( SELECT product_id, sale_date - INTERVAL '1 day' * rn AS grp FROM DateSequence ) SELECT product_id, COUNT(*) AS max_consecutive_days FROM DateGroups GROUP BY product_id, grp ORDER BY max_consecutive_days DESC;
This solution uses a combination of row numbers and date arithmetic to group consecutive sale dates and then counts the length of these groups to find the maximum streak.
